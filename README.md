# Отслеживание волейбольного мяча в видео

Дипломный проект: онлайн-система детекции и трекинга волейбольного мяча в видеопотоке.
Детекция — предобученная свёрточная сеть (ONNX, seq=9), трекинг — собственный multi-track
трекер на словарях, верификация гипотез — CatBoost-классификатор по геометрии траектории.

```
Видео → grayscale 512×288 → буфер 9 кадров → ONNX VballNet → heatmap 288×512
      → threshold 0.5 → контуры → центр масс largest blob
      → пересчёт координат в разрешение исходного видео
      → Detection{frame, visible, x, y}
      → трекер (multi-track, velocity prediction, gap cleaner)
      → выбор main ball по stability score
      → 13 признаков траектории → CatBoost (P ≥ 0.8) → confirmed / отброшен
      → отрисовка
```

---

## Возможности

- Детекция мяча в каждом кадре видео: ONNX-модель `VballNet` (9 кадров контекста, 512×288, grayscale).
- Декодинг тепловой карты: threshold → `findContours` → центр масс по moments, без `argmax`
  (устойчивее к нескольким локальным максимумам).
- Multi-track трекер: одновременно живёт до 15 гипотез, каждая — обычный словарь `Track`.
- Сопоставление детекций и треков по евклидову расстоянию до предсказанной позиции, в два прохода
  (confirmed / unconfirmed) с разными порогами.
- Линейная экстраполяция позиции (`pred_calculate`) — мяч не теряется на коротких пропусках.
- Отбор главного мяча по метрике стабильности траектории.
- CatBoost-фильтр: 13 признаков геометрии трека → бинарная классификация «мяч / не мяч»;
  прошедшие треки помечаются `confirmed = True` и живут дольше.
- Прогресс-бар в консоли, live-превью в окне OpenCV.

## Быстрый старт

### Зависимости

Python 3.13. Пайплайну нужны четыре пакета: `numpy`, `opencv-python`, `onnxruntime`, `catboost`.

```bash
uv venv
uv pip install numpy opencv-python onnxruntime catboost
```

Без uv — то же самое через обычный pip:

```bash
python3.13 -m venv .venv && source .venv/bin/activate
pip install numpy opencv-python onnxruntime catboost
```

`onnxruntime` на macOS сам подключает `CoreMLExecutionProvider` (см. `detection.load_model`),
на остальных платформах инференс идёт на CPU.

### Настройка

Все параметры вынесены в `scr/config.py`. Модели лежат в репозитории, а вот видео для
прогона — нет (файлы `*.mp4` в `.gitignore`), поэтому `INPUT_VIDEO_PATH` нужно
переопределить на свой файл:

```python
BALL_MODEL_PATH      = "model/ball.onnx"       
CAT_BOOST_MODEL_PATH = "model/catboost_ball_model.cbm"  
INPUT_VIDEO_PATH     = "test_input.mp4"     
```

`FPS`, `VIDEO_WIDTH`, `VIDEO_HEIGHT` читаются из входного видео автоматически при импорте
модуля — руками их задавать не нужно.

### Запуск

```bash
python -m scr.main_ball
```

Скрипт идёт по видео в один проход и показывает окно с результатом в реальном времени
(красный круг — сырая детекция, зелёный — подтверждённый main ball, цифра в углу — id трека).
Окно закрывается по завершении видео. Прогресс печатается в консоль.

## Детекция — `scr/detection.py`

| Функция | Назначение |
|---|---|
| `load_model` | создаёт `ort.InferenceSession` |
| `model_params` | достаёт имена входного/выходного слоя и их формы |
| `preprocess_for_onnx` | BGR → grayscale → resize 512×288 → float32 / 255.0 |
| `input_tensor` | стэк буфера в тензор `(1, 9, 288, 512)` |
| `inference` | `session.run` |
| `heatmap_decoder` | threshold → контуры → центр масс |
| `original_dimension` | пересчёт координат из сетки 512×288 в разрешение видео |
| `create_dict` | сборка словаря `Detection` |

`heatmap_decoder` берёт последний кадр выходной последовательности `output[0, -1, :, :]`,
бинаризует по порогу, находит внешние контуры, выбирает **самый крупный по площади** и считает
центр масс через `cv2.moments`. Если контуров нет или `m00 == 0` — возвращается
`(0, -1, -1)`, то есть детекция с `visible = 0`.

На каждый кадр сеть выдаёт **0 или 1** кандидата — это осознанное упрощение пайплайна.

## Трекер — `scr/tracker.py`

Трек — это `TypedDict` (`MyTypes.Track`):

```python
frame_idx, x, y, pred_x, pred_y, size_frame, size_sec,
dist_x, dist_y, first_frame, last_frame, confirmed
```

`all_track` — словарь `int → Track`, общий пул гипотез на всём видео.

| Функция | Назначение |
|---|---|
| `create_track` | новый трек из одной детекции |
| `update_track` | добавление точки, пересчёт метрик и прогноза |
| `match_detection` | сопоставление детекции с треком (два прохода) |
| `gap_cleaner` | удаление треков по длине разрыва |
| `clearing_track_queue` | ограничение размера пула: вытесняется самый старый неподтверждённый трек |
| `stability_track_analyzer` | метрика стабильности траектории |
| `select_main_ball` | выбор трека с максимальным score |
| `pred_calculate` | линейная экстраполяция позиции |
| `track_size` | длительность трека в кадрах и секундах |
| `track_distance` | размах траектории по осям X и Y |

### Прогноз позиции

`pred_calculate` работает в двух режимах:

- последняя точка валидна (`x[-1] >= 0`) — скорость считается как разность двух последних
  точек, нормированная на разницу номеров кадров, и прибавляется к текущей позиции;
- последняя точка потеряна — берётся средняя скорость по последним 10 шагам от реальных точек
  и прогноз строится от последней известной позиции.

### Матчинг

`match_detection` возвращает пустой словарь, если `visible == 0`. Иначе — два прохода:

1. по `confirmed`-трекам, порог **100 px**;
2. если совпадения нет — по неподтверждённым трекам, порог **30 px**.

Расстояние — евклидово между `track["pred_x"][-1], track["pred_y"][-1]` и детекцией.

### Метрика стабильности

```
speed    = |v_mean|                       # модуль средней скорости
var      = var(vx) + var(vy)              # суммарная дисперсия скорости
score    = speed / (1 + var) * log(n + 1) # n — число шагов
```

Мяч летит плавно, поэтому его дисперсия скорости мала, а длина траектории велика.
Неподвижные и «рваные» объекты получают низкий score. `select_main_ball` возвращает трек
с максимальным score.

## CatBoost-фильтр

### Признаки — `scr/feature_generation.py`

| Признак | Что описывает |
|---|---|
| `dist_x`, `dist_y` | размах траектории по осям |
| `ratio` | извилистость: длина пути / расстояние между первой и последней точкой |
| `lenght` | число точек в треке |
| `std_x`, `std_y` | стандартные отклонения координат |
| `speed_mae` | средняя скорость движения |
| `mean_angle` | средний угол поворота между шагами, градусы |
| `line_rmse` | RMSE отклонения от ортогональной регрессии (PCA) |
| `line_max_error` | максимальный выброс от этой прямой |
| `parabola_rmse` | RMSE от полинома 2-й степени по номерам кадров |
| `mean_gap` | средний интервал между детекциями, кадры |
| `ratio_gap` | доля переходов, где кадры были потеряны |

Основные метрики (`ratio`, `speed_mae`, `std_x/std_y`, `mean_gap`) считаются векторизованно
через `np.diff` + `np.hypot`. Исключения — `turn_angle` (угол между векторами по итогам `cross`/`dot`
считается в цикле) и `mean_speed_calculate`, где `d_t` берётся из `frame_idx`, а не из индекса.

### Важность признаков

По результатам обучения три признака дают практически всю discriminative силу модели:
`ratio_gap` (16.75), `mean_angle` (12.67), `dist_x` (1.68). Мяч почти никогда не теряет кадры
подряд, а шум — наоборот, поэтому регулярность трека и плавность поворотов отличают мяч
от любых других объектов в кадре сильнее, чем абсолютные координаты.

### Фильтрация

`cat_boost_filter` пропускает трек, если `predict_proba(...)[0][1] >= 0.8` — вероятность класса
«мяч». Обратите внимание на индекс: `predict_proba` возвращает `[p_not_ball, p_ball]`,
индекс `1` — нужный класс.

Фильтр применяется **только к main-треку**: сначала `select_main_ball` выбирает лучшую
гипотезу, затем CatBoost либо подтверждает её (`confirmed = True`), либо отбрасывает.
Это дешевле, чем прогонять классификатор по всем трекам, и не даёт шуму закрепиться.

## Архитектурные решения

| Решение | Значение |
|---|---|
| Обработка | онлайн, один проход, без постфактум анализа |
| Представление треков | словари (`TypedDict`), а не классы |
| Детекций на кадр | 0 или 1 |
| Сопоставление | евклидово расстояние до предсказанной позиции |
| Обновление трека | только при наличии детекции, без пропагации при `visible = 0` |
| Отбор main ball | score = `mean_speed / (1 + var) * log(n + 1)` |
| Подтверждение | CatBoost на 13 признаках, порог 0.8 |
| Разрыв | confirmed 30 кадров, unconfirmed 5 |

## Notebooks

- **`main.ipynb`** — тот же пайплайн, адаптированный под ноутбук. Отличие от `main_ball.py`:
  треки сохраняются в словарь, после обработки координаты разворачиваются в плоский
  `frame → (x, y), track_id`, и отдельным проходом по видео рисуется итоговое видео.
  Используется для демонстрации и сохранения артефактов.
- **`experimetns_and_problems.ipynb`** — два исследования:
  1. сравнение предсказания позиции без нормализации по кадрам и с ней
     (выигрывает нормализованная версия — она и легла в `pred_calculate`);
  2. три версии `match_detection` на искусственных сценариях, показывающих, почему
     однопроходный поиск по confirmed-трекам ломал сопоставление, и как это чинится
     двумя проходами с разными порогами.
- **`instruction_for_main.md`** — какие поля конфига нужно заполнить перед запуском ноутбука.

## Результаты

- **Качество классификатора треков: 93.2% accuracy** на тестовой выборке
  (метрика обучения — LogLoss, ~600 размеченных треков).
- Обработка идёт в потоковом режиме: один проход по кадрам, без постобработки,
  решение принимается на лету.

### Производительность

Замер на M1 Air: 2.93 минуты видео (~5400 кадров) — 7.37 минут обработки.
Узкие места:

- инференс ONNX на CPU (основной bottleneck);
- `select_main_ball` — каждый кадр заново считает score для всех треков пула,
  проходя по всем их точкам;
- декодинг видео и копирование кадра в `tools.py`.

Отдельная оптимизация: замена `cv2.waitKey(1)` на `cv2.pollKey()` — на 40-минутном видео
(~80 000 кадров) это дало экономию около 0.7 минуты.

## Ограничения

- **Нет размеченного ground truth.** Качество трекинга оценивается визуально, поэтому
  формальных метрик точности (precision/recall, IoU треков) у проекта нет — только
  accuracy классификатора. Это главное, что стоит понимать про текущие результаты.
- `scr/main_ball.py` работает как live-превью и не сохраняет видео на диск;
  для получения записи нужно использовать `notebooks/main.ipynb` или дописать `VideoWriter`.
- Видео для прогона в репозиторий не коммитится, поэтому `INPUT_VIDEO_PATH` в `scr/config.py`
  указывает на несуществующий `test_input.mp4` — путь нужно заменить на свой файл.
- Склейка умерших подтверждённых треков и интерполяция пропусков не реализованы:
  если мяч ненадолго исчезает, трек обрывается и начинается заново.
- Скорость работы ограничена CPU-инференсом; батчинг, многопоточное чтение и
  GPU-провайдер не задействованы.

## Планы развития

- online-склейка умерших confirmed-треков и интерполяция дыр;
- фильтрация ложных детекций в `heatmap_decoder` по площади контура;
- применение CatBoost ко всем трекам, а не только к main;
- определение площадки (YOLO seg) и разметка зон касания / падения;
- ускорение стрима.
